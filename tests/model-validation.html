T1D Simulator — Model Behaviour Checks

Automated tests of the simulation model (Hovorka 2004 + physiological extensions). Tests physiological plausibility, circadian variation, dose-response, fixed characters, activity, stress, sleep and metabolic adaptation.

How the tests are performed

Most tests run the same PhysiologyEngine and Simulator facade as the game, but without the interactive game UI. A minimal mock environment supplies the DOM references required by the facade, and game-over is disabled so severe trajectories can be observed to completion.

Each test creates a fresh deterministic model instance with a fixed character or an explicitly stated technical parameter isolation. Character weight, ISF and ICR are fixed model inputs — not patient data. Starting BG is set with clampBG(), which adjusts both plasma (Q1) and peripheral (Q2) glucose proportionally and runs 15 sim-minutes for equilibration — this avoids discontinuities at the start of the charts.

Then a scenario (e.g. insulin dose, meal, exercise) is simulated by calling the model in internally subdivided steps of at most one minute, while most charts sample every five minutes. The resulting curves are plotted on canvas and compared with expected physiological values.

Default character: Erik — fixed adult model (70 kg, ISF=3.0 mmol/L/U, ICR=10 g/U), unless otherwise specified.

Coverage and scope

Scenario chapters show interpretable model behaviour from matched, deterministic starting points. Advanced diagnostics isolate internal equations and thresholds that are difficult to see in ordinary gameplay.

This page intentionally does not duplicate every unit, API and gameplay regression test. Input validation, event routing, CGM fault states, HAAF state transitions and game rules are covered by the automated JavaScript and browser suites.

Passing these checks means that the implemented model behaves as specified by its current equations and documented calibration ranges. It does not establish clinical performance for an individual person.
