# Skabelon til review af spilleroplevelsen

## 1. Konklusion

1. Den vigtigste finding.
2. Den anbefalede retning.
3. Hvad der ikke bør ændres endnu.

## 2. Scope og metode

1. Målgruppe og spiltilstande.
2. Desktop, mobil eller begge.
3. Kodefiler og dokumentation læst.
4. Browserflow testet eller kun udledt af kode.
5. Evidenssøgning og cut-off-dato.

## 3. Nuværende flow

For hver spillergruppe:

1. Trin fra load til kørende simulation.
2. Minimumsantal klik.
3. Antal reelle beslutninger.
4. Antal blokerende skærme.
5. Forsinkelser og animationer.
6. Kodehenvisninger.

## 4. Findings

Brug denne struktur:

1. Titel og prioritet.
2. Observation med fil- og linjereference.
3. Konsekvens for spilleren.
4. Evidensniveau.
5. Usikkerhed.

## 5. Mulige løsninger

For hver løsning:

1. Ændring.
2. Forventet mekanisme.
3. Fordel.
4. Risiko eller tradeoff.
5. Eksisterende komponenter, der kan genbruges.
6. Berørte filer.
7. Mindste test.

## 6. Anbefalet rækkefølge

1. Små rettelser med høj sikkerhed.
2. Prototype eller mockup.
3. Observeret brugertest.
4. Begrænset implementering.
5. Browservalidering og analytics.

## 7. Måleplan

1. Primært produktmål.
2. Primært læringsmål.
3. Sekundære oplevelsesmål.
4. Guardrails.
5. Segmenter: ny/tilbagevendende, desktop/mobil og sprog.

## 8. Etisk og T1D-specifikt tjek

1. Fiktiv simulation er tydelig.
2. Ingen personlig behandlingsvejledning.
3. Neutral og håbefuld tone.
4. Ingen skyld, tvang eller frygtbaseret retention.
5. Reversible fejl og genfindelig hjælp.
6. Fysiologisk troværdighed er bevaret.

## 9. Begrænsninger

1. Hvad der ikke blev testet.
2. Hvilke anbefalinger der er designinferenser.
3. Hvilke målgrupper der mangler direkte input fra.
4. Hvilke produktbeslutninger der kræver brugerens godkendelse.

## 10. Referencer

Brug stabile DOI-, PubMed-, officielle myndigheds- eller institutionslinks. Markér industri-praksis særskilt fra forskning.
